# 个人 CMDB 前端设计方案

版本：1.0 · 日期：2026-10-27

状态：下一版设计方案，包含行业调研、页面与交互规范、视觉语言和首批生成素材。本文件描述设计目标；具体功能是否已实现，以代码和 README 为准。

本文是下一轮前端重设计的依据。根目录 `DESIGN.md` 仍记录现有界面规范；实施时需把已落地的设计规则同步回该文件，避免长期维护两套规则。

## 1. 设计结论

推荐采用**以任务为中心、围绕资源组织信息的个人工作台**。

这是一套针对本项目的综合判断，并非某个机构发布的“行业第一设计风格”。它由任务导向、资源详情作为信息中心、渐进披露、适度信息密度、可解释状态和一致交互共同组成。

设计首先帮助使用者完成五件事：找到资源、打开入口、查明归属、理解依赖、处理待办。品牌感来自清晰的排版、稳定的布局、准确的资源身份和少量有用途的专属插画。

## 2. 当前界面诊断

本轮结合现有页面代码与项目预览截图判断，尚未进行用户测试。

| 当前表现 | 对使用的影响 | 设计调整 |
| --- | --- | --- |
| 首页四个同权重统计卡片，最近更新和资源分布占主要空间 | 进入后先看到数量，需要继续寻找待处理事项 | 将“需要关注”和常用入口提前，统计摘要退居辅助位置 |
| 侧栏同时铺开九类资源 | 主导航与资源筛选混在一起，纵向扫描成本偏高 | 主导航保留任务入口；类型作为资源页筛选或可折叠分组 |
| 近黑背景和多个深灰面板的层级接近 | 所有区块显得同样重要，页面缺少节奏 | 明确外壳、工作区域、浮层三层表面，减少无意义的卡片嵌套 |
| 部分导航说明、身份信息使用 10–11px 字体 | 中文和辅助说明难以阅读 | 正文 14px，元信息 12px 起；用间距和内容取舍控制密度 |
| 类型图标已具备，但同类型资源主要依靠名称区分 | 快速定位常用服务仍需逐行阅读 | 统一使用图标或 favicon、名称、主标识和归属构成身份单元 |
| 生命周期已与在线状态做文字区分，但缺少完整的状态表达体系 | 容易把人工记录、探测结果、同步新鲜度理解成同一种状态 | 分别呈现生命周期、观测状态和数据新鲜度，并附来源与时间 |
| 空状态偏通用文字提示 | 第一次使用时缺少产品识别度和明确的第一步 | 用专属插画配一个明确动作；区分未录入、筛选无结果与请求失败 |

这些判断针对现有信息组织和视觉权重，不代表其基础功能全部缺失。首页已有资料补全提示，只是位置与权重不足；资源列表已有搜索、筛选和排序，需要把它们发展成完整的工作区域。

## 3. 设计原则

### P1. 先给出下一步动作

每个页面必须回答“我在这里能完成什么”。首页优先显示可处理的事项；列表帮助定位和比较；详情帮助理解一个资源并继续操作。

数量、图表和介绍文案都服务于这些任务。无法引导判断或操作的统计，不占据首页核心位置。

### P2. 资源是信息组织中心

同一个资源从搜索、项目、同步结果进入时，使用相同身份单元和详情结构。关系有方向和语义，例如“服务部署在主机上”“域名指向入口”，避免含糊的“相关资源”。

服务的入口、部署与关联域名保持可追踪，不能只把它们写进备注。

### P3. 先展示常用信息，再展开复杂度

资源列表默认只显示最有助于识别和判断的字段。详情以概要、入口与部署、关系、历史组织内容，类型专属字段按语义分组。

新增资源先选择类型，展示少量必填项。可选字段保持可发现；不会为了制造“极简”而隐藏日常常用操作。

### P4. 密度由内容和任务决定

默认舒适模式；频繁维护台账时可切换紧凑模式。两种模式共享相同字号、字段语义和操作顺序，主要调整行高、内边距和区域间距。

空白用于分组，不能制造大面积空洞。表格用于比较，卡片用于识别具有独立身份的对象。

### P5. 状态必须说明依据

状态至少区分三个维度：

- 生命周期：计划中、使用中、停用等人工管理状态。
- 观测状态：可访问、探测失败、未检测等某次观测结果。
- 数据新鲜度：来源、最后成功同步或检查时间、是否过期。

例如：“使用中 · 最近探测失败 · 12 分钟前”。探测失败不直接宣称服务已经宕机；未检查也不使用成功色。

颜色与图标、文字共同表达含义，避免仅靠红绿区分。该原则对应 [WCAG 对颜色使用的要求](https://www.w3.org/TR/WCAG22/#use-of-color)。

### P6. 快速操作与可恢复性并存

常见入口就近放置：复制地址、打开服务、编辑用途、关联项目。操作完成应反馈结果；失败保留用户输入并给出恢复路径。

删除、解绑、覆盖采用不同文案，说明影响的记录与关系。软删除应提供恢复入口；并发修改提示用户重新载入或比较内容，避免静默覆盖。

### P7. 视觉表达有固定职责

主色表达当前选择与主要动作；状态色表达结果；资源身份颜色表达类型或来源。三类颜色不混用。

专属插画用于引导和空状态。工作区域以文字、图标、表格、真实数据可视化为主。所有真实关系图由数据生成并允许交互。

### P8. 单人使用也需要一致性

名称、状态、时间、错误和动作顺序在各页面保持统一。个人产品的简化重点是导航、配置和流程，不降低数据可信度与可读性。

## 4. 信息架构

### 4.1 主导航

| 分组 | 入口 | 核心任务 | 范围 |
| --- | --- | --- | --- |
| 工作空间 | 总览 | 处理关注事项、访问常用资源 | 本次重设计主线 |
| 工作空间 | 资源 | 搜索、筛选、比较和维护全部资源 | 本次重设计主线 |
| 工作空间 | 项目 | 按用途查看一组资源及其关系 | 本次重设计主线 |
| 数据管理 | 同步中心 | 连接来源、检查同步结果、确认发现候选 | 本次重设计主线 |
| 数据管理 | 设置与数据 | 连接配置、偏好、数据管理 | 本次重设计主线 |
| 生命周期 | 续费与到期 | 查看账期、到期和处理记录 | 依赖后续产品能力，当前不创建可点击空壳 |

资源类型在资源页顶部提供快捷筛选；侧栏可保留折叠的“资源类型”分组。常用项目或保存视图可固定，但不默认铺开所有类型、所有项目和全部视图。

回收站置于设置与数据或资源管理的次级入口，避免占用主要导航位置。

### 4.2 全局外壳

- 桌面侧栏宽 224–240px，顶栏高 56px；内容区独立滚动。
- 顶栏负责当前位置、全局搜索和全局状态；页面标题区承载页面操作。
- 全局搜索按名称、域名、IP、标签、用途寻找资源，结果显示类型与主标识。
- `⌘/Ctrl+K` 仅在真正实现对应搜索或命令面板后展示提示；输入框内不拦截常规编辑快捷键。
- 桌面内容横向边距 24–32px；宽表格允许使用更多空间，表单限制阅读宽度。

## 5. 核心页面设计

### 5.1 总览：个人日常工作台

首屏顺序：页面标题与动作 → 简洁摘要 → 需要关注 → 常用资源 → 项目与近期动态。

| 区域 | 内容与行为 |
| --- | --- |
| 页面标题 | “总览”，附简短状态说明；主要动作为“添加资源” |
| 摘要 | 资源总数、在用资源、项目数量；紧凑展示，每个数字可进入对应集合 |
| 需要关注 | 资料缺失、同步失败等有证据的事项；每条包含原因、来源时间和具体处理动作 |
| 常用资源 | 收藏的服务与控制台入口；名称、入口域名、项目、上次观测时间；支持打开与复制 |
| 项目 | 资源数量与关键入口，进入项目详情；不以零散统计取代项目的用途 |
| 近期动态 | 新增、修改、关联、同步等实际事件，注明来源和时间 |

首次无资源时，用 `resource-workspace-v1.png` 与“开始建立资源台账”引导，主操作“添加第一个资源”，次操作“连接数据源”。

未来的续费、证书到期、备份过期等事项，只有在对应数据与计算规则存在后进入关注区域。真实数据没有趋势时不绘制虚构趋势线。

### 5.2 资源：可持续使用的台账

- 标题区：集合名称、当前结果数量、添加资源。
- 视图区：全部、收藏、最近更新及保存视图；未实现的视图不显示为可用功能。
- 筛选区：搜索、类型、项目、生命周期；展开后显示标签和来源等更多条件。
- 活跃筛选以可移除标签展示，提供“清除筛选”，筛选写入 URL。
- 默认列：资源身份、用途或项目、生命周期、主要入口、更新时间；按类型调整可选列。
- 选择行后出现批量工具栏，明确已选数量和操作范围。
- 默认名称链接进入完整详情；需要连续比较时可打开预览面板，保留当前筛选与滚动位置。
- 支持列显隐、排序和密度偏好。筛选覆盖整个集合，而非当前可见行。
- 空数据、无筛选结果、请求失败使用不同的内容和动作。

排序、字段选择、密度和错误反馈的设计依据为 [Cloudscape 表格模式](https://cloudscape.design/patterns/resource-management/view/table-view/)。具体选择范围与翻页行为需在实现时明确，并在工具栏中提示，避免歧义。

### 5.3 资源详情：一个资源的信息中心

顶部身份区包含：资源图标、名称、类型、主标识、用途、项目、生命周期。来源和更新时间作为独立元信息展示。主要操作依据类型显示，例如服务“打开入口”、域名“访问域名”；无有效入口时不提供无效按钮。

| 内容区 | 内容 |
| --- | --- |
| 概览 | 用途、归属、类型专属属性、关键状态和来源 |
| 入口与部署 | 公网入口、管理入口、运行主机、端口和容器等实际记录 |
| 关系 | 按语义列出指向与被指向的资源；先提供可读列表，图形视图作为后续补充 |
| 历史 | 操作、时间、来源和变更前后值；敏感内容脱敏 |

标签数量随资源能力变化。没有部署概念的账号，不为了套用通用模板而展示空的部署标签。

关键入口可一键复制；完整地址可查看。超长域名和 IP 在信息区允许换行，不能仅靠不可发现的悬浮提示才能读取。

### 5.4 新增与编辑

- 少量字段采用对话框；字段较多或涉及多组关系时采用独立页面，避免嵌套弹窗。
- 首组：类型、名称、用途、所属项目；后续显示类型专属字段与可选关系。
- 手工输入、外部导入和系统推断值有清楚区别；推断值允许确认或修正。
- 必填与可选的标记一致；错误紧邻字段，同时给出修正建议。
- 提交中防止重复提交；失败保留输入；有未保存改动时再提醒离开。
- 长表单使用固定操作区，但不能遮住当前字段或键盘焦点。

### 5.5 项目

项目卡片展示名称、用途、资源数量和常用入口。详情展示项目简介、关键资源、资源集合和真实关系。资源分组优先按角色，例如“入口”“运行环境”“数据”，允许退回按类型浏览。

关系图需要范围过滤、选中详情和文字替代列表。第一轮无需实现全局复杂拓扑画布。

### 5.6 同步中心

每个连接器展示来源身份、配置状态、最后成功时间、最近执行结果和明确动作。区分“已配置”“连接可用”“上次同步成功”，不能用一个绿色圆点概括。

同步结果区分新增、更新、跳过、失败。发现候选先供检查确认，再导入资源；局部失败应保留已知数据，并说明失败范围。

未配置连接器使用 `connect-source-v1.png` 配置引导。进行中和失败使用真实进度、原因和动作，避免插画掩盖错误。

持久任务历史、定时同步与字段级差异预览需要后端能力支持，设计保留结构，前端不能伪造已经存在的记录。

## 6. 视觉语言

方向：**清晰、有秩序、有资源身份感的深色控制台**。

用可读文字、稳定网格、表面层级和节制的紫色强调建立品质感。保持中文工作台的直接表达，减少口号和重复说明。

### 6.1 语义色彩提案

以下为下一版候选值，不代表已替换运行界面的 CSS。

| Token | 色值 | 用途 |
| --- | --- | --- |
| canvas | `#0D1017` | 页面底色 |
| shell | `#10131B` | 导航与顶栏 |
| surface | `#141822` | 主要工作面 |
| surface-raised | `#1A1F2B` | 弹层、提升层、局部悬停 |
| border | `#2B3343` | 结构分隔；控件边界需额外检查可辨识度 |
| text | `#F3F5F8` | 主要文字 |
| text-secondary | `#A4ADBD` | 辅助说明 |
| text-muted | `#8C97AA` | 次级元信息 |
| primary | `#6C5CE7` | 主要动作 |
| primary-text | `#B6ABFF` | 链接、选择与焦点相关文字 |
| success | `#69D6A2` | 有证据的成功或健康状态 |
| warning | `#EBC171` | 需要关注 |
| danger | `#F08A92` | 错误或破坏性动作 |

按 sRGB 相对亮度公式检查的示例：白字/primary 4.86:1，text/surface 16.25:1，text-secondary/surface 7.85:1，text-muted/surface-raised 5.59:1。这只是候选实色对的检查，不等同于界面整体通过无障碍验收；透明叠加、悬停、禁用、控件轮廓和焦点状态仍需逐项检查。

默认保持深色；颜色全部使用语义变量，为未来主题适配保留结构。状态和资源类型使用不同组件语义，避免把类型色误读为健康状态。

### 6.2 字体、间距与密度

| 项目 | 规则 |
| --- | --- |
| 中文正文 | 系统中文字体：PingFang SC / Microsoft YaHei，14px，行高约 22px |
| 拉丁文字 | Inter 优先，系统无衬线回退；不依赖外部 CDN 才能正常显示 |
| 页面标题 | 24px / 32px，600；详情标题可按名称长度调整 |
| 分区标题 | 16px / 24px，600 |
| 元信息 | 12px / 18px 起，真实业务信息不使用 10px |
| 技术标识 | JetBrains Mono / 系统等宽，12–13px；仅用于域名、IP、端口、ID 等 |
| 间距 | 4、8、12、16、24、32px |
| 表格行高 | 舒适 52–56px，紧凑 40–44px；多行内容允许增高 |
| 控件 | 桌面常规高 36px，紧凑 32px；触屏主要点击区域目标至少 44px |
| 圆角 | 输入与按钮 6–8px，面板 10–12px；标签可用胶囊形 |

不同区块用标题、间距和分隔线形成层级，避免每组字段都再包一张卡片。浮层可使用轻阴影帮助理解遮挡关系。

### 6.3 资源身份

统一身份组件包含图标或可靠 favicon、名称、主标识，以及按上下文显示的类型和归属。类型以线性图标表达；同类型实例优先靠名称和主标识辨认。

可用 favicon 失败时回退至字母或类型图标。第三方品牌标识保持其身份用途，不用生成图片仿造 Cloudflare、云厂商等商标。无需给九种类型分别生成位图图标。

## 7. 交互、响应与无障碍

| 场景 | 必需反馈 |
| --- | --- |
| 首次加载 | 与页面结构匹配的骨架，避免整页反复闪烁 |
| 后台刷新 | 保留原数据，局部提示刷新中；失败标明显示的仍是旧数据 |
| 保存成功 | 明确成功对象；即时更新相关视图 |
| 保存失败 | 保留输入、解释失败，并允许重试 |
| 数据冲突 | 显示版本已变更，提供重新载入或后续比较路径 |
| 无资源 | 首次使用引导和添加动作 |
| 筛选无结果 | 显示当前条件，提供清除或调整筛选 |
| 权限或认证失效 | 说明需要重新登录，不伪装成无资源 |
| 来源不可用 | 给出来源、最后成功时间、失败范围和恢复动作 |

键盘可访问所有主要操作；焦点可见，关闭弹层后返回触发位置。表格排序、选中和加载状态有可理解的语义。图标按钮有名称，悬浮提示不能成为唯一说明。

桌面以表格和完整详情为主；中等宽度折叠侧栏，预览面板不挤压主要内容；手机使用导航抽屉，筛选进入可关闭面板，列表优先保留身份、关键状态和入口。完整表格可作为显式切换视图，避免整页意外横向滚动。

动效以 120–180ms 的状态变化和小范围面板过渡为主。遵守减少动态效果偏好；不使用持续旋转或闪烁表达正常运行。

## 8. 美术资源体系

### 8.1 已生成首批素材

使用内置 image_gen，原始文件为带真实 alpha 透明通道的 PNG，均为 1254 × 1254。已目视检查构图、色彩、无文字与无第三方标识，并验证 alpha 范围为 0–255。

| 文件 | 概念 | 使用位置 |
| --- | --- | --- |
| `apps/web/public/art/resource-workspace-v1.png` | 把服务、存储、域名收纳到同一个工作空间 | 全新台账、首次录入引导 |
| `apps/web/public/art/connect-source-v1.png` | 外部来源与本地资源目录建立连接 | 同步中心首次配置引导 |

视觉规则：等距模型、哑光材质、冷白与石墨灰主体、少量靛紫连接结构。没有内嵌文案，中文由真实 HTML 排版；图片不承担实时状态与真实拓扑。

### 8.2 使用规范

- 首次引导建议显示宽 180–220px，局部空状态 120–160px；使用 `object-fit: contain`。
- 一屏原则上只有一处主要插画，控制其与任务内容的竞争。
- 装饰性插画使用空 alt；必要说明由相邻文字完成。
- 显式指定宽高，按场景延迟加载；不要把原图作为全屏壁纸。
- 原始 PNG 为设计源素材，总计约 1.85MB；正式接入时按展示尺寸导出优化资源并检查 alpha 边缘。
- 文件采用稳定名称和版本号，生成提示词保存在同目录的 `art-prompts.json`。

后续素材优先按真实页面需要追加：项目未归集、导入检查、完成备份等。筛选无结果采用轻量图标与文字；加载错误采用错误组件。先验证首批风格在真实界面中的表现，再扩展整套插画。

## 9. 实施顺序与能力边界

| 阶段 | 交付 | 依赖或限制 |
| --- | --- | --- |
| 1. 视觉与结构 | 语义 tokens、排版、导航、资源身份、状态与空状态组件；重排总览、列表、详情 | 主要可基于现有资源核心完成 |
| 2. 日常操作 | 收藏、常用入口、保存视图、列配置、密度、预览与批量操作 | 需要相应偏好存储、交互与部分 API 扩展，现有版本未全部具备 |
| 3. 数据可解释性 | 同步结果摘要、字段来源、历史差异、过期提示 | 需明确字段来源和观测时间模型，持久同步任务仍需补齐 |
| 4. 生命周期 | 到期与费用、备份恢复工作流、项目关系图 | 属于后续 PRD 能力，不能仅靠前端模拟完成 |

本轮交付设计文档与首批素材，不把上述阶段标记为已实现。正式改造时按完整用户任务逐页验收，避免只做组件替换。

## 10. 设计验收清单

以下是验收目标，尚未进行实测，不作为现有版本的测试结果。

- 在包含 100 条资源的固定样本中，通过名称、域名或 IP 能找到目标并打开入口；保留可观察的用时记录。
- 首屏可直接判断有没有需要处理的事项，每条事项有原因与动作；无相关数据时不宣称一切健康。
- 从项目或搜索进入同一资源，身份、状态和详情内容一致。
- 在列表查看详情再返回，筛选、排序和阅读位置得到保留。
- 能从生命周期、观测结果和来源时间判断一条状态的含义。
- 200% 缩放、390px 手机宽度与常见桌面宽度下，主要任务可完成，内容不被固定区域遮挡。
- 主要文字的实际色对通过对比度检查；主要流程可用键盘完成，焦点位置可辨认。
- 空台账、筛选无结果、首次配置、加载失败、后台刷新失败有可区分的画面和动作。
- 插画在目标显示尺寸下边缘自然、主题清楚，不出现文字伪影；图片加载不推动周围内容跳动。
- 预览数据均有示例标记，未来能力和真实状态不由静态演示内容伪装。
